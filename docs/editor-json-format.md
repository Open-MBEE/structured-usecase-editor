# Structured Use Case Editor JSON Format

Version: 0.8.0

The Structured Use Case Editor JSON format is the editor's save/open interchange format for structured use case models. Files normally use the `.ucm.json` extension.

The format is intentionally simple JSON so it can be generated by tools, edited by hand when necessary, stored in GitHub, and reopened by the Structured Use Case Editor.

## Status

This is a practical interchange format for the reference editor. It is not yet an OMG standard and should not be confused with the SysML v2 textual notation generated by the editor.

The editor uses this JSON format to persist both:

- Semantic model information, such as actors, use cases, scenarios, steps, requirements, and relationships
- Editor information, such as diagram layout, selected element, and palette state

## File Extension

Recommended extension:

```text
.ucm.json
```

The v0.8 editor may also accept older `.suc.json` files for backward compatibility, but new files should use `.ucm.json`.

## Top-Level Object

A saved model is a JSON object with this general shape:

```json
{
  "metaclass": "UseCaseModel",
  "id": "model-registration-login-system",
  "name": "RegistrationLoginSystemModel",
  "nextNodeNumber": 6,
  "nextEdgeNumber": 6,
  "selectedNodeId": "uc-register",
  "selectedEdgeId": "",
  "paletteTool": "select",
  "connectKind": "",
  "connectSourceId": "",
  "actors": [],
  "useCases": [],
  "relationships": []
}
```

## Top-Level Fields

| Field | Type | Purpose |
| --- | --- | --- |
| `metaclass` | string | Identifies the file as a use case model. Use `UseCaseModel`. |
| `id` | string | Stable model identifier. |
| `name` | string | Model name used for display and generated SysML package names. |
| `nextNodeNumber` | number | Editor counter for creating new diagram nodes. |
| `nextEdgeNumber` | number | Editor counter for creating new relationships. |
| `selectedNodeId` | string | Editor state for the selected node. May be empty. |
| `selectedEdgeId` | string | Editor state for the selected relationship. May be empty. |
| `paletteTool` | string | Editor palette selection. Usually `select`. |
| `connectKind` | string | Editor state while creating a connection. Usually empty in saved files. |
| `connectSourceId` | string | Editor state while creating a connection. Usually empty in saved files. |
| `actors` | array | Actor elements in the model. |
| `useCases` | array | Use case elements in the model. |
| `relationships` | array | Relationships between actors and use cases or between use cases. |

## Actor Object

```json
{
  "id": "actor-user",
  "name": "User",
  "layout": {
    "x": 70,
    "y": 250,
    "width": 74,
    "height": 116
  }
}
```

| Field | Type | Purpose |
| --- | --- | --- |
| `id` | string | Stable actor identifier. |
| `name` | string | Actor display name. |
| `layout` | object | Diagram position and size. |

## Use Case Object

```json
{
  "id": "uc-register",
  "name": "Register Account",
  "layout": {
    "x": 260,
    "y": 115,
    "width": 230,
    "height": 82
  },
  "specification": {}
}
```

| Field | Type | Purpose |
| --- | --- | --- |
| `id` | string | Stable use case identifier. |
| `name` | string | Use case display name. |
| `layout` | object | Diagram position and size. |
| `specification` | object | Structured use case specification. |

## Layout Object

```json
{
  "x": 260,
  "y": 115,
  "width": 230,
  "height": 82
}
```

Coordinates are editor canvas coordinates. Width and height are used by resizable use case bubbles in v0.8.0 and later.

## Specification Object

```json
{
  "name": "Register Account",
  "preconditions": [
    "User is not currently signed in."
  ],
  "requirements": [
    "REQ-AUTH-01: The system shall allow a new user to create an account."
  ],
  "relatedTestCases": [
    "TC-AUTH-REG-01"
  ],
  "scenarios": []
}
```

| Field | Type | Purpose |
| --- | --- | --- |
| `name` | string | Specification name, normally matching the use case name. |
| `preconditions` | array of strings | Conditions that must be true before the use case begins. |
| `requirements` | array of strings | Requirement references or requirement statements. |
| `relatedTestCases` | array of strings | Related test case identifiers. |
| `scenarios` | array | Basic, alternate, and exception scenarios. |

## Scenario Object

```json
{
  "id": "N",
  "type": "nominal",
  "postcondition": [
    "User account is created."
  ],
  "steps": [
    {
      "number": 1,
      "text": "User opens the registration form."
    }
  ]
}
```

Scenario types:

- `nominal` for the basic scenario
- `alternate` for valid alternate behavior
- `exception` for error or off-nominal behavior

Alternate and exception scenarios may include `condition`, `branchStep`, and `rejoinStep`.

```json
{
  "id": "4E",
  "type": "exception",
  "condition": "Invalid registration information",
  "branchStep": 4,
  "rejoinStep": 3,
  "postcondition": [
    "Invalid registration information is rejected and the account is not created."
  ],
  "steps": []
}
```

| Field | Type | Purpose |
| --- | --- | --- |
| `id` | string | Scenario identifier. `N` is conventionally used for the nominal scenario. |
| `type` | string | `nominal`, `alternate`, or `exception`. |
| `condition` | string | Branching condition for alternate and exception scenarios. |
| `branchStep` | number | Nominal scenario step where this scenario branches. |
| `rejoinStep` | number | Nominal scenario step where this scenario rejoins. |
| `postcondition` | array of strings | Conditions true after the scenario completes. |
| `steps` | array | Ordered scenario steps. |

## Step Object

```json
{
  "number": 1,
  "text": "User opens the registration form."
}
```

The editor renumbers steps as they are edited. Generated SysML v2 uses these step numbers to name step actions.

## Relationship Object

```json
{
  "id": "edge-register-login",
  "type": "precedes",
  "label": "«precede»",
  "sourceId": "uc-register",
  "targetId": "uc-login",
  "layout": {}
}
```

Supported relationship types:

- `association`
- `include`
- `extend`
- `invoke`
- `precedes`

| Field | Type | Purpose |
| --- | --- | --- |
| `id` | string | Stable relationship identifier. |
| `type` | string | Relationship type. |
| `label` | string | Diagram label. May be empty for associations. |
| `sourceId` | string | ID of the source actor or use case. |
| `targetId` | string | ID of the target actor or use case. |
| `layout` | object | Optional relationship layout metadata. |

## Semantic Fields vs. Editor Fields

Semantic fields describe the use case model itself:

- `actors`
- `useCases`
- `relationships`
- `specification`
- `preconditions`
- `requirements`
- `relatedTestCases`
- `scenarios`
- `steps`
- `postcondition`
- `condition`
- `branchStep`
- `rejoinStep`

Editor fields help the browser editor reopen and display the model:

- `layout`
- `nextNodeNumber`
- `nextEdgeNumber`
- `selectedNodeId`
- `selectedEdgeId`
- `paletteTool`
- `connectKind`
- `connectSourceId`

## Minimal Valid Model

```json
{
  "metaclass": "UseCaseModel",
  "id": "model-minimal",
  "name": "MinimalUseCaseModel",
  "nextNodeNumber": 3,
  "nextEdgeNumber": 1,
  "selectedNodeId": "uc1",
  "selectedEdgeId": "",
  "paletteTool": "select",
  "connectKind": "",
  "connectSourceId": "",
  "actors": [
    {
      "id": "actor1",
      "name": "User",
      "layout": { "x": 40, "y": 100, "width": 74, "height": 116 }
    }
  ],
  "useCases": [
    {
      "id": "uc1",
      "name": "Perform Task",
      "layout": { "x": 220, "y": 120, "width": 180, "height": 72 },
      "specification": {
        "name": "Perform Task",
        "preconditions": [],
        "requirements": [],
        "relatedTestCases": [],
        "scenarios": [
          {
            "id": "N",
            "type": "nominal",
            "postcondition": [],
            "steps": [
              { "number": 1, "text": "User performs the task." }
            ]
          }
        ]
      }
    }
  ],
  "relationships": [
    {
      "id": "edge1",
      "type": "association",
      "label": "",
      "sourceId": "actor1",
      "targetId": "uc1",
      "layout": {}
    }
  ]
}
```
